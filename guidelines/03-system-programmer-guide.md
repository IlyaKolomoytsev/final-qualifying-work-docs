# Руководство системного программиста

Источник: [022](<sources/guidelines-for-the-2022-final-qualification-project/extracted/pages/022.txt>)-[025](<sources/guidelines-for-the-2022-final-qualification-project/extracted/pages/025.txt>), форматирование см. [09-formatting.md](09-formatting.md).

## Общие требования

- РСП не имеет жесткого ограничения по объему.
- Средний объем РСП: 15-30 страниц.
- РСП оформляется по ГОСТ 19.503-79.
- Требования к форматированию приведены в приложении А методички.

## Типовая структура РСП

1. Титульный лист.
2. Аннотация.
3. Содержание.
4. 1. Общие сведения о программе.
5. 2. Структура программы.
6. 3. Настройка программы.
7. 4. Проверка программы.
8. 5. Дополнительные возможности.
9. 6. Сообщения системному программисту.
10. Приложения.

## Наполнение разделов

### Титульный лист

Оформляется по приложению Б и материалам курса ВКР на `edu.vstu.ru`.

### Аннотация к РСП

Аннотация оформляется только на русском языке.

В ней нужно указать:

- тему работы;
- краткое описание содержимого документа;
- количество страниц, рисунков, таблиц, формул и приложений в РСП с учетом приложений;
- ключевые слова.

### 1. Общие сведения о программе

Нужно указать:

- назначение программы;
- функции программы;
- сведения о технических средствах, обеспечивающих выполнение программы;
- сведения о программных средствах, обеспечивающих выполнение программы.

### 2. Структура программы

Нужно привести сведения:

- о структуре программы;
- о составных частях программы;
- о связях между составными частями;
- о связях с другими программами.

### 3. Настройка программы

Нужно описать действия по настройке программы на условия конкретного применения.

Возможные темы:

- настройка под состав технических средств;
- выбор функций;
- настройка компилятора или среды выполнения;
- установка переменных среды;
- требования к операционной системе.

В разделе нужны поясняющие примеры, если они применимы.

### 4. Проверка программы

Нужно описать способы проверки, которые позволяют сделать общее заключение о работоспособности программы.

Раздел должен включать:

- контрольные примеры;
- методы прогона;
- ожидаемые результаты;
- проверку требований, описанных в ТЗ;
- подробные действия тестировщика;
- результаты, которые тестировщик должен получить на каждом этапе.

### 5. Дополнительные возможности

Нужно описать:

- дополнительные функциональные возможности программы;
- способы выбора этих возможностей.

### 6. Сообщения системному программисту

Нужно указать:

- тексты сообщений, выдаваемых при настройке;
- тексты сообщений, выдаваемых при проверке;
- тексты сообщений, выдаваемых при выполнении программы;
- описание смысла сообщений;
- действия, которые нужно выполнить по этим сообщениям.

### Приложения

В приложениях РСП могут быть дополнительные материалы:

- примеры;
- иллюстрации;
- таблицы;
- графики.

## Чек-лист РСП

- [ ] Структура соответствует ГОСТ 19.503-79.
- [ ] Есть титульный лист, аннотация и содержание.
- [ ] Описаны назначение и функции программы.
- [ ] Описаны технические и программные средства.
- [ ] Описана структура программы и связи компонентов.
- [ ] Описана настройка программы с примерами.
- [ ] Описана проверка программы по требованиям ТЗ.
- [ ] Даны пошаговые действия тестировщика и ожидаемые результаты.
- [ ] Описаны дополнительные возможности.
- [ ] Перечислены сообщения и действия по ним.
