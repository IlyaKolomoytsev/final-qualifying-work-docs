## Проблема 3. Валидация методологически уязвима

### 3.1. Нет описания процедуры эксперимента

**Что не так.** По нынешнему тексту воспроизвести эксперимент невозможно. Не сказано:

- Что именно подавалось на вход модели?
- Какая полоса частот использовалась — нижняя граница, верхняя, средняя?
- Какая модель поглощения — Торп или Франсуа-Гаррисон, и почему именно она?
- Какие значения солёности, температуры, pH, глубины (для Франсуа-Гаррисона)?
- Какой коэффициент геометрического расхождения n?
- Что считалось «максимальной дальностью» — расстояние, на котором SINR падает до порога?
- Сколько прогонов? Симуляция детерминированная или стохастическая?

**Что нужно сделать.** Добавить подраздел «Методика валидации» (или абзац в начале раздела) с явным описанием:

- входных параметров модели;
- алгоритма определения «максимальной дальности приёма» (например: бинарный поиск по дистанции, при которой SINR на приёмнике достигает порога γ_th);
- значений физических параметров среды (T, S, pH, глубина);
- выбранной модели поглощения с обоснованием;
- значения коэффициента n;
- используемой полосы частот для каждого модема (нижняя / верхняя / средняя — с обоснованием).

### 3.2. Сравниваются несопоставимые величины

**Что не так.** «Максимальная дальность приёма» из спецификации производителя — это **маркетинговая величина**, измеренная в неизвестных условиях (глубина, тип дна, профиль скорости звука, BER-порог, тип модуляции). Сравнивать с ней детерминированный расчёт через SINR — это сравнение разных по природе величин.

**Что нужно сделать.** Явно проговорить это **как ограничение метода валидации**, а не как недостаток модели. Сформулировать примерно так:

> Следует подчеркнуть, что паспортная максимальная дальность приёма является интегральной характеристикой, измеренной производителем в специфических, в общем случае неизвестных условиях (профиль скорости звука, уровень шума на акватории, тип модуляции, целевой BER). В связи с этим использование таких данных в качестве эталонных вносит неустранимую неопределённость в оценку точности модели и задаёт нижнюю границу достижимого MAPE при выбранной методике валидации.

### 3.3. Произвольно выбранные параметры валидации

**Что не так.**

- Уровень шума **46 dB взят единым для всех модемов**, но в таблице есть модемы на 10 kHz и на 120-180 kHz. Спектральная плотность шума в океане отличается на этих частотах на порядок (закон ≈ -17 dB/декада в области выше 1 kHz). Единый шум **искусственно завышает ошибку модели на ВЧ-модемах**.
- Единый порог SINR 14.8 dB взят как «среднее по типам модуляции», хотя у разных модемов модуляция разная.

**Что нужно сделать.**

- Либо использовать **частотно-зависимую модель шума** (формула Wenz или хотя бы кусочно-постоянную аппроксимацию для разных диапазонов).
- Либо явно зафиксировать допущение «единый уровень шума как первое приближение» и **проанализировать, как это влияет на результат для ВЧ-модемов** (например, отдельно посчитать MAPE для подгрупп НЧ / СЧ / ВЧ модемов).
- Аналогично — либо подобрать порог SINR под тип модуляции каждого модема (если данные доступны), либо явно обосновать использование единого порога как первое приближение.

### 3.4. Спектральная плотность vs мощность шума в полосе

**Что не так.** В тексте указано:

> За уровень шума возьмём значение равное 46 dB ref. uPa²/Hz, что равно 40000 uPa²/Hz

Это **спектральная плотность**. Для расчёта SINR нужна **мощность шума в полосе сигнала** (то есть интеграл спектральной плотности по полосе). В тексте не показано, как делается этот переход — а это ключевой шаг расчёта. Комиссия за это зацепится.

**Что нужно сделать.** Добавить явный расчёт:

> Мощность шума в полосе сигнала вычисляется как N = N₀ · B, где N₀ — спектральная плотность шума, B — ширина полосы модема (из таблицы характеристик).

Со ссылкой на соответствующую формулу из главы 2.

### 3.5. Интерпретация результатов неаккуратна

**Что не так.**

- «MAPE 25% — это _средний_ показатель» — на основании чего «средний»? Нет ни baseline-модели для сравнения, ни эталонной точности из литературы.
- Фраза «обусловлен неполнотой имеющейся информации» звучит как **оправдание**, а не как анализ.
- **R² = 0.68 при 25 модемах с разными частотами и мощностями — это успех**, а не «средний показатель». Модель объясняет 68% дисперсии дальности.

**Что нужно сделать.** Переформулировать вывод по результатам валидации:

> Полученное значение коэффициента детерминации R² = 0.68 свидетельствует о том, что разработанная модель объясняет около 68% дисперсии паспортной дальности приёма по выборке из 25 модемов с различными частотными диапазонами, излучаемой мощностью и областями применения. С учётом того, что эталонные значения дальности измерены производителями в неизвестных и неоднородных условиях, а валидация проведена при единых параметрах шума и порога SINR, такая точность подтверждает корректность реализованных в модели физических зависимостей и применимость модели для виртуальных испытаний приёмопередатчиков на ранних этапах проектирования.

### 3.6. Нет графика

**Что не так.** Регрессионная валидация без визуализации — это половина работы. Метрики без графика не дают понимания, **где именно** модель ошибается.

**Что нужно сделать.** Добавить **scatter plot**:

- ось X: паспортная дальность (km);
- ось Y: предсказанная моделью дальность (km);
- диагональ y = x (идеальная модель);
- желательно — разная окраска точек по диапазонам частот (НЧ / СЧ / ВЧ);
- подписи отдельных точек с названиями модемов (или хотя бы выбросов).

Один график здесь стоит больше, чем все четыре метрики вместе. Он сразу покажет, систематическая ошибка или случайная, и на каких модемах модель отклоняется сильнее всего.

## Мелкие замечания

### Таблица модемов слишком большая

25 строк без какого-либо анализа — это слишком много для основного текста. Варианты:

- **унести таблицу в приложение**, а в основном тексте оставить агрегирующие характеристики (диапазоны частот, мощностей, дальностей);
- либо разбить на 2-3 более коротких таблицы по диапазонам частот.

### MSE избыточна

MSE в м² не несёт смысловой нагрузки рядом с MAE (м) и MAPE (%). Её можно убрать без потерь — либо заменить на RMSE (м), которая хотя бы в одних единицах с MAE.

### Формулировка «задача сводится к задаче регрессии»

Технически неточно. Это **задача проверки точности модели по эталонным данным** (regression evaluation), а не «задача регрессии» (где модель строится из данных). Лучше переформулировать: «оценка точности модели на эталонных данных в постановке задачи регрессионного типа».
